# 官網設計規格 — AI 黃金自動跟單系統

日期：2026-08-24
狀態：待實作
範圍：五個子專案裡的第一個（官網）。會員端／訊號端換皮、會員後台、i18n 擴張各自獨立。

---

## 1. 目標與非目標

**目標**：做一個對外行銷官網，展示產品功能、四種訂閱方案與下載入口，繁中／英文可切換，
視覺與互動臨摹 TradingView，但品牌軸換成黃金。

**非目標（本階段不做）**：

- 不做線上金流／註冊流程。CTA 導向下載頁與聯繫方式。
- 不改 `copy_trader/` 任何後端程式碼。
- 不動會員端／訊號端 UI（下一個子專案）。
- 不做後端 API。官網是純靜態，唯一的外部呼叫是 TradingView 免費行情 Widget。

**已知落差（記錄，本階段不處理）**：
`membership.py` 的等級是 `trial / basic / advanced / flagship`（體驗／基礎／進階／旗艦），
官網對外用 `FREE / PLUS / PRO / PREMIUM`。官網先照對外命名做呈現，
後端 tier 對齊留到會員端子專案處理。

## 2. 智慧財產界線

TradingView 的 logo、圖示、字型（EuclidCircularSemibold）、攝影素材一律不使用、不下載、不重繪。

可以用的：

- **設計語言**：版面骨架、色階邏輯、字級節奏、圓角與動效參數。這些是通用做法，不受保護。
- **`lightweight-charts`**：TradingView 自家開源，Apache 2.0，明確允許商用。
- **免費行情 Widget**：TradingView 公開提供給第三方網站嵌入，依其嵌入條款使用（需保留來源標示）。

所有圖示自己畫成 inline SVG。

## 3. 設計系統

### 3.1 色彩

```
/* 中性（深色為預設，也是唯一主題） */
--c-bg          #0A0A0B   頁面底
--c-surface     #141416   卡片
--c-surface-2   #1E1E21   卡片內凹 / hover
--c-surface-3   #2A2A2E   再上一層 / 分隔塊
--c-line        #26262A   細線
--c-line-strong #3A3A40   hover 邊框

--c-text        #EDEDEF   主文
--c-text-2      #A0A0A8   次要
--c-text-3      #82828C   說明 / 停用

/* 品牌金 */
--c-gold-400    #F0C65C
--c-gold-500    #D4A017   主
--c-gold-600    #A87C10
--c-gold-wash   rgba(212,160,23,.12)

/* 漲跌（沿用業界慣例，與使用者提供的會員端 mockup 一致） */
--c-up          #089981
--c-up-2        #22AB94   深底上用
--c-down        #F23645
--c-down-2      #F7525F   深底上用

/* 方案分色（取自使用者提供的方案表） */
--c-plan-free    #FFFFFF
--c-plan-plus    #3179F5
--c-plan-pro     #A855F7
--c-plan-premium #F0C65C
```

深色是唯一主題。行銷站不做日夜切換 —— 交易產品的行銷站幾乎都只有深色，
而且雙主題會讓漸層與光暈的調校成本翻倍，這階段不值得。

### 3.2 字型

```
--f-display  'Manrope', system-ui, sans-serif        標題（Euclid Circular 的免費替代）
--f-sans     'Noto Sans TC', -apple-system, BlinkMacSystemFont,
             'Segoe UI', Roboto, sans-serif           內文（中英共用）
--f-mono     'JetBrains Mono', ui-monospace, monospace  數字 / 價格
```

Google Fonts 載入，只取實際用到的字重（Manrope 600/800、Noto Sans TC 400/500/700）。
所有數字欄位加 `font-variant-numeric: tabular-nums`。

### 3.3 字級（沿用 TradingView 實測慣例）

```
10 / 11 / 12 / 13 / 14 / 16 / 18 / 20 / 24 / 28 / 36 / 48 / 64 / 72 px
```

Hero 桌機 72px、平板 48px、手機 36px。內文 16px，說明文字 14px，標籤 12px。

### 3.4 間距與圓角

8px 基準：`4 8 12 16 24 32 48 64 96 128`。
圓角：`4`（小控件）`8`（按鈕／輸入）`12`（小卡）`16`（大卡）`999`（pill）。
內容最大寬 `1200px`，左右留白桌機 32px、手機 20px。

### 3.5 動效

```
--e-out    cubic-bezier(.215,.61,.355,1)     一般進場
--e-spring cubic-bezier(.45,1.45,.8,1)       彈性強調
淡入淡出   opacity .2s ease-in-out
位移       transform .35s var(--e-out)
微互動     background-color 60ms, transform 120ms var(--e-out)
```

捲動進場用 `IntersectionObserver` 加 `.is-in` class，一次性觸發，不重播。
全站尊重 `prefers-reduced-motion: reduce` —— 開啟時所有位移與捲動動畫關閉，只留即時顯示。

## 8. 雙語機制

**做法**：HTML 標記 `data-i18n="key"`，字串放 JSON，載入時 JS 替換。

```
website/i18n/zh-Hant.json
website/i18n/en.json
```

- 屬性翻譯用 `data-i18n-attr="placeholder:key,aria-label:key2"`。
- 語言決定順序：`?lang=` 參數 → `localStorage.site_lang` → `navigator.language` → 預設 `zh-Hant`。
- 切換時同步更新 `<html lang>`、`localStorage`、網址參數（`history.replaceState`，不重載）。
- HTML 內先寫繁中作為 fallback，JS 失效時網站仍可讀。
- 每頁 `<head>` 放 `hreflang` 交替連結。

**不做的**：不用 i18n 函式庫、不做每語言一份 HTML、不做建置期產生。
理由是這站規模小，執行期替換的成本可忽略，而免建置讓部署簡單到只要丟檔案。

## 14. 設計修訂（2026-08-24，第一期驗收後）

第一版做出來「很像 AI 生成的頁面」。把 tw.tradingview.com 的 HTML 與 72 支 CSS bundle
實際抓下來拆解後，找到六個具體差異，本節取代第 3 節與第 5 節的對應內容。
完整拆解見 [`2026-08-24-tradingview-layout-method.md`](2026-08-24-tradingview-layout-method.md)。

### 14.1 字級（原訂值全部偏小約一半）

| 項目 | 第一版 | 修訂後 | TradingView 實測 |
|---|---|---|---|
| 段落主標 h2 | 48px / lh 1.12 | `clamp(34px, 5.6vw, 72px)` / lh 1.02 | 40 → 100px / lh 1.0 |
| 副標 lede | 18px | `clamp(17px, 1.4vw, 24px)` | 18 → 24px |
| 功能標題 h3 | 18px | `clamp(24px, 2.4vw, 36px)` | 24 → 36px |
| 功能內文 | 14px | 16px | 16 → 18px |

大標的 line-height 必須貼近 1.0。行高一放鬆，標題就散掉，那種份量感全來自這一點。
中文另外用 `:lang(zh-Hant)` 放寬字距與行高 —— 方塊字吃不了西文那種負字距。

### 14.2 垂直節奏

改用 TradingView 的五級制（桌機 200 / 160 / 120 / 80 / 48px，四個斷點各一組）。

**注意**：`--v-1: 200px` 在他們的系統裡是「兩個段落之間」的距離。
第一版我上下各給一個 `--v-1`，等於把間距做成兩倍，畫面出現整片空白。
正確寫法是 `padding-block: calc(var(--v-1) / 2)`。

### 14.3 容器寬度

`1200px` → `1480px`。窄容器是頁面顯得侷促、像後台管理介面的原因之一。
