# 發版流程

給你自己看的。會員拿到的是 [安裝說明.md](安裝說明.md)。

---

## 一句話版本

```bash
git tag v1.0.1 && git push origin v1.0.1
```

GitHub Actions 會同時建出 Windows 和 macOS 的四個安裝檔，做成一個**草稿** Release。去 GitHub 的 Releases 頁確認過再按發布。

---

## 為什麼 Windows 不能在 Mac 上建

PyInstaller 打包的是「執行它的那台機器上的 Python 直譯器 + 那個平台的原生模組」。沒有交叉編譯這回事 —— 在 macOS 上生不出 `.exe`。

所以 Windows 那份只有兩條路：

1. **GitHub Actions**（推薦，上面那行指令）
2. 在一台 Windows 電腦上跑 `python scripts/build-release.py`

## 本機建置

```bash
python3 scripts/build-release.py              # 兩個角色都建
python3 scripts/build-release.py --client     # 只建會員端
python3 scripts/build-release.py --skip-installer   # 只要 .app，不包 DMG
```

產出在 `dist/installers/`。

Windows 上還要先裝 [Inno Setup 6](https://jrsoftware.org/isdl.php)，不然只會產出資料夾、不會有安裝檔。

### 建置腳本會幫你做的事

1. **前置檢查** —— 先 import 一次核心模組。相依壞掉的話現在就炸，而不是等會員按下按鈕才炸
2. **建置** —— 每次都清掉舊產物，避免改了 spec 卻沿用上一輪的結果
3. **冒煙測試** —— **真的把打包好的程式跑起來**，打 `/api/status`、`/api/stats`、`/api/market` 三支 API

   這一步不能省。打包最常見的失敗不是建置失敗，而是**建置成功但一啟動就 ModuleNotFoundError** —— 這個專案有大量「在函式裡才 import」的寫法，PyInstaller 的靜態分析不一定抓得到。那種錯誤只有跑起來才看得到。

4. **打包** —— macOS 產 DMG（含 Applications 捷徑，拖進去就裝好），Windows 呼叫 Inno Setup

冒煙測試沒過的話腳本會回傳 exit code 1 並且明講「先別發出去」。

## 改了程式碼之後

### 加了新模組？

如果新模組是**在函式裡面才 import** 的，要加進 `packaging/pyinstaller/_common.py`。

四份 `.spec` 都從那個檔案拿清單 —— 不要各自去改 spec。之前四份分開維護的下場是 `central-windows.spec` 的 hiddenimports 整個變成空的，打出來的訊號中心不會夾帶 EA 檔案。

找出所有函式內 import 的方法：

```bash
python3 - <<'PY'
import ast, pathlib
for f in pathlib.Path('copy_trader').rglob('*.py'):
    if '__pycache__' in str(f): continue
    tree = ast.parse(f.read_text(encoding='utf-8'))
    for node in ast.walk(tree):
        if not isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)): continue
        for n in ast.walk(node):
            if isinstance(n, ast.ImportFrom) and n.module and n.module.startswith('copy_trader'):
                print(f'{n.module}  ← {f}')
PY
```

### 改了 EA？

EA 原始碼會自動夾帶進安裝檔（`_common.py` 的 `datas()`），不用做什麼。

但**現有會員必須自己重新編譯**。EA 改動要在發版說明裡講清楚，不然他們裝了新版程式卻配舊版 EA，症狀會很難查 —— 通常是「某些功能靜靜地不見了」而不是明確報錯。

目前的降級處理：舊版 EA 只寫 `rates_M1.json`，後端會自動用 M1 合成大週期，`available` 會照實反映，前端只顯示根數夠的週期。所以不會壞，只是功能少。

## 版本號

改三個地方，要一致：

| 檔案 | 位置 |
|---|---|
| `scripts/build-release.py` | `VERSION = "1.0.0"` |
| `packaging/inno/*.iss` | `#define MyAppVersion` 的預設值 |
| `packaging/pyinstaller/*-macos.spec` | `info_plist` 的 `CFBundleShortVersionString` / `CFBundleVersion` |

推 tag 的時候 tag 名要跟這個版本對得上。

## 簽章：目前沒有，成本與效果

兩個平台的安裝檔都**未經簽章**，使用者第一次開啟會看到警告。這不影響功能，但確實會讓一部分人不敢裝。

想解決的話：

| 平台 | 需要什麼 | 大約成本 | 效果 |
|---|---|---|---|
| Windows | 程式碼簽章憑證（OV 或 EV） | 約 US$200–400／年 | OV 憑證要累積信譽才會不跳警告，EV 憑證立刻生效 |
| macOS | Apple Developer Program | US$99／年 | 簽章 + 公證（notarize）後完全不會有警告 |

macOS 這邊 CP 值明顯高很多 —— 99 鎂就能讓「無法驗證開發者」的警告完全消失。

如果之後買了憑證，簽章要加在 `build-release.py` 的 `make_dmg()` 裡（`codesign` → `xcrun notarytool submit` → `xcrun stapler staple`），憑證放進 GitHub Secrets。

## 檢查清單

發版之前：

- [ ] `python3 scripts/build-release.py` 在本機全過（冒煙測試綠燈）
- [ ] 官網的 placeholder 績效數字處理掉了（`website/assets/js/site-config.js` 的 `showStats`）
- [ ] EA 有改的話，發版說明裡有寫「請重新編譯 EA」
- [ ] 三個地方的版本號一致
- [ ] tag 推上去，等 Actions 綠燈
- [ ] Release 草稿裡四個檔案都在（Windows ×2、macOS ×2）
- [ ] 自己先下載裝一次再發布
